# M12 参考图驱动的空间重组计划 0.1

> 状态：`SUPERSEDED_BY_VISUAL_REFERENCE_CONTRACT_1_0`
> 日期：2026-08-15
> 前置：M12 计划 0.1（文档 28）；M12-F 仍为 `PLANNED / USER_REVIEW_REQUIRED`
> 影响层级：`L0_PRESENTATION + BOUNDED_L1_COMPONENT`

## 1. 触发事实

M12-D/E 的功能、键盘、可访问性、生产 Chromium 和清理证据仍然有效，但用户在真实浏览器中否决了
当前表现系统的整体气韵。否决对象不是某一个色值，而是以下已观察到的空间问题：

1. 深色 masthead 同时承载品牌、状态与十字导航，导航展开后像遥控器而非院落导览；
2. SectionFrame、信息面板、指标卡和断言卡反复嵌套，形成大卡片包中卡片包小卡片；
3. Run Catalog 的账册关系已经存在，却被重色表头、状态盒和外围框线削弱；
4. 网格背景、金线、朱色与深色块同时争夺注意力，主题压过了证据阅读顺序。

本计划的抽象空间语言已被用户提供的完整视觉参考集取代。请使用
`docs/47-m12-visual-reference-contract.md` 及其引用图作为视觉施工合同；真实 Run、状态、路由、焦点与
只读边界仍是唯一权威事实。

## 2. 本轮唯一主要变量

```text
workbench_presentation_composition = reference_guided_palace_ledger
```

保持不变：M0-M11 Schema、Bundle/Manifest 校验、Catalog/API、Verdict、URL/history、文件导入、
`data-testid`、键盘和浏览器证据语义。若实现触及上述任一 L2/L3 事实，立即停止本切片。

## 3. 锁定的表现规则

### 3.1 门阙与院落分层

- 深青 masthead 只承担品牌与全局身份；不再容纳公共视图导航或当前 Run 状态；
- 四个公共视图导航位于 masthead 下方的浅色院落，始终以固定可见的 `1 -> 2 -> 3 -> 4` 顺序出现；
- 当前视图以结构朱和金色门槛立住，其他三项退为金墨；不重复显示当前视图标签；
- 保留原来的四类公共视图、URL/history 与焦点目标，但视觉不再模拟遥控器式十字开合；
- 不新增没有真实功能的“设置”“账户”或装饰性顶栏入口。

### 3.2 一次边界、连续账册

- 页面骨架、一个区段和一条记录是三种不同层级；同一事实不得同时获得三层边框与底色；
- Run Catalog 保留一个外层账册边界和一条深色题签，Run 本身是连续可点击行；
- 状态用紧凑标签、文字、图形与行侧标记表达，不扩张为独立卡片；
- 详情中的 SectionFrame 只保留区段分隔。概览字段、断言、账册、时间线和边界内容使用行、列、
 细分隔与排版层级；不得把每个字段再装入卡片；
- 空、加载、无效和隐私重选等确实需要被隔离的状态可以保留单一 state surface，不能再套一层。

### 3.3 色彩与材质

- 移除页面根节点与 masthead 的规则网格。浅底保持明确纸白/砖灰关系，不模拟雾、柔焦或泛灰；
- 深青、矿物金和结构朱只承担空间定位。结构朱只作为极小的轴线、当前视图下划线和门槛；
- FAIL/ERROR 仍只由独立警示朱 token 表达；不得因参考图的朱色按钮而混淆证据状态；
- 不引入图片、远程字体、CDN、贴图或无语义的仿古图案。

### 3.4 建筑节点的翘角与金瓦

- 直角可以在少数大尺度结构节点转为极小的斜切/翘角，使用 CSS 边界和伪元素表达，不引入屋檐图片；
- 矿物金的“金瓦”只可以压在当前公共视图、Catalog 题签以及确实独立的空/错误 state surface 顶边；
- 普通断言行、状态标签、账册单元、事实字段和截图卡不得增加翘角或金瓦；
- 翘角不能裁切文字、焦点环、长 hash、状态轮廓或交互命中区；forced-colors 下退化为普通矩形边界。

### 3.5 公共导航的护城河轴

- 四个公共入口下方使用低对比、纯 CSS 的波纹水线，作为“护城河”式的导航轴；
- 水线只表达有限公共视图的固定阅读顺序，不表示网络数据流、实际并行、因果强度或结果传递；
- 当前项的文字、序号、状态与路由仍是主信息；水线在 forced-colors 和 reduced-motion 下退化为普通细线；
- Pairing 保留 `BASELINE -> TREATMENT -> RESTORED_BASELINE -> NEGATIVE_CONTROL` 的明确箭头和角色文字，
  不再额外复制护城河装饰。

## 4. 实施顺序

1. 迁移 masthead、门槛和 CrossAxisNavigation，先让四项护城河导航在真实桌面/移动页面中成立；
2. 将 Runs 工具条做成连续的四段控制带，将 Catalog 收束为一张连续账册；
3. 收束 Run 详情的概览、断言、账册和边界，删除卡片套卡片；
4. 以同一规则收束 Comparison、Pairing、Batch 和 Browser Evidence 的局部重复容器；
5. 在生产构建上检查正向、负向、损坏、Catalog、派生视图、移动、键盘、Console/Network；
6. 用户进行整体审美复核后，才决定是否重新进入 M12-F。

## 5. 本切片退出条件

- 参考图的三项空间规则在真实 M11 Catalog 和正/负 Bundle 中可见；
- 无“页面框 -> 区段框 -> 字段/行框”三层嵌套；
- 四项导航的点击、Tab、左右方向键、URL/history 和焦点归还保持成立；
- 根节点不横向溢出，移动端没有为了模仿桌面而保留无功能的大空白；
- 自动化、类型检查、lint、生产构建和适用的真实浏览器门禁通过。

本计划不构成 M12 完成或冻结结论。用户的审美确认和 M12-F 的全部硬门禁仍不可省略。
