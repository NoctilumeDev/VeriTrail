# VeriTrail 0.12.2 Release Notes

> 状态：`RELEASED / MAINTENANCE FROZEN`
>
> 当前公开稳定 Core：`0.12.2`
>
> 发布坐标：`0.12.2`

VeriTrail 0.12.2 是 Core 0.12.1 之后的有界维护版。它只修复一个公开组合路径：`veritrail demo`
在同级 staging 中创建 Catalog、再将整个 demo 原子发布到最终目录后，Catalog 仍必须从出生时就绑定
最终 Artifact root，使公开 wheel 生成的 demo 能直接交给官方 `catalog-serve`。

本维护版不重开 M0–M14，不改变 Catalog Schema、`catalog_id`、Run identity、Verdict、公共
`build_catalog()` 语义或 Workbench，也不移动或改写 `v0.12.0`、`v0.12.1`。验证器仍然 fail-closed；
完整搬移已经发布的 demo 后，`catalog-serve` 仍必须精确拒绝 `ARTIFACT_ROOT_MISMATCH`。

## 根因与修复边界

0.12.1 的 demo producer 在 staging 中扫描 Artifact root 并写入位置摘要，然后才原子改名。Bundle、
Verdict、Catalog 内容与 `catalog_id` 没有漂移，过期的是 producer 冻结的物理位置绑定。0.12.2 让
Catalog 模块内部的受限入口验证 `stage/artifacts -> FINAL/artifacts` 同父目录映射，并在扫描 staging
内容时只计算一次最终 Artifact root 摘要，同值写入 SQLite 与 Manifest。

受限入口拒绝不同父目录、错误相对布局、已有最终目标、symlink／reparse staging 或 Artifact root，
以及 Windows 会改写的尾点／尾空格名称。未预期内部异常以稳定 `DEMO_INTERNAL_ERROR` 非零退出，
不输出 traceback 或原始本机路径。精确授权范围和既有边界见
[Core demo Catalog 最终位置绑定维护合同](74-core-demo-catalog-binding-maintenance-contract.md)。
