## 1. 触发事实

此前两种实现路径均被用户在真实浏览器中否决：

1. 向旧的“标题卡 -> 工具卡 -> 目录卡”结构叠加水纹、金瓦、整框和朱漆，结果像贴图压在后台组件上；
2. 删除这些材料后，页面虽较干净，却退化为普通浅棕色工作台，未接近参考图的秩序、气韵与材质关系。

因此问题不是继续寻找更好的单张贴图，也不是再调一组 token。当前视觉实现的前提已经失效：

```text
错误前提：不嵌套卡片 = 不使用建筑性框架
正确前提：数据事实不嵌套卡片；页面级空间可以拥有一层有职责的建筑框架
```

参考图中的命令门和 Catalog 正殿不是两张“卡片皮肤”。前者界定真实导入操作，后者界定整个连续账册；
行、状态、字段仍不再各自套卡。R3 只重建这一层空间语法，不能借此改变产品行为。

## 1.1 参考层级与借鉴边界

R3 不再凭局部 CSS 灵感推进。每个布局判断必须先落入以下三层参考之一，并明确其权限：

| 层级 | 来源 | 可决定什么 | 不可决定什么 |
| --- | --- | --- | --- |
| 视觉验收权威 | 文档 47 的七张用户参考图 | 构图、比例、留白、材质、色相、建筑节点的层级与克制 | 数据、路由、控制、状态语义或任何新功能 |
| 行为权威 | `m11-v0.12.0` 与既有 Workbench 合同 | Catalog/API、文件导入、URL/history、焦点、键盘、真实 Run 与 Verdict | 视觉风格或页面级空间组织 |
| 外部布局借鉴 | [Allure 3](https://github.com/allure-framework/allure3)、[Directus](https://github.com/directus/directus)、[Vben Admin](https://github.com/vbenjs/vue-vben-admin) | 证据阅读优先级、连续账册、稳定应用外壳的通用规律 | 任何截图、品牌、图标、资产、控件、侧栏或通用后台皮肤 |

外部参考形成的三条结论是：

1. 证据系统的状态与追溯关系必须是第一阅读层，装饰不能替代或盖住结论；
2. 多条同类事实应属于一张连续账册，而不是同权重的卡片网格；
3. 全局导航需要稳定，但 VeriTrail 采用参考图中的上方中轴壳层，不回退为侧栏式后台或 KPI 大盘。

因此，GitHub 只帮助回答“真实工具如何安排阅读密度和稳定外壳”；它不替代用户参考图回答“验迹应当长成什么样”。不得下载、复制、裁切或运行时引用上述项目的截图、图标、字体、Logo、CSS 或品牌元素。

## 2. 保留、退休与唯一变量

唯一主要变量为：

```text
catalog_presentation_method = reference_first_spatial_composition
```

以下事实必须原样保留：

- Catalog/API、Bundle/Manifest 校验、Verdict 与状态语义；
- 真实 M11 Catalog 数据、长 Run ID、失败/中止/待定事实和本地导入隐私边界；
- URL/history、焦点归还、Tab/方向键、`data-testid`、原生 file input 与可访问名称；
- 同源只读网络、无 CDN、无远程字体、无假控制、无截图替换页面。

以下表现实现必须退休，不能再以追加 override 的方式修补：

- 当前 Catalog 公共前场的实验性 `m12-*` 贴图、金瓦、水纹和整框规则；
- 把原始整张金瓦、整框或朱红操作图拉伸为任意尺寸背景的做法；
- 把同一视觉角色同时写入 `palace-theme.css`、基础组件规则和末尾修正层的多所有者规则。

“推倒重来”只指表现建筑。不得 `git reset`、不得丢弃已有功能或历史事实；现有工作树中的候选仍保留，
新实现必须有清楚的 CSS/组件所有权，旧规则在替换切片中被明确删除或迁出。

## 3. R3 的空间蓝图

R3 以参考图的 `1440px` 桌面构图为唯一首要目标。响应式、其他公共视图和 Run Detail 都不在本合同的
第一个实现切片中。

```text
全宽深青主殿（品牌与真实边界文字）
    -> 单一居中的金色中轴过门
    -> 浅宣纸院落中的四项公共导航 + 云水过渡
    -> 无框页面标题与少量轴线标记
    -> 一座真实来源操作门（3 个示例入口 + 1 个本地导入入口）
    -> 一座 Catalog 正殿（深青题签 + 一条连续 Run 账册）
```

构图规则：

1. 主殿、命令门和 Catalog 正殿是三个不同尺度的空间节点；它们不是同样大小、同样粗细的矩形。
2. 命令门是唯一可操作的门槛。导入入口占其朱红部分，三个示例入口是同一门中的分段真按钮。
3. Catalog 正殿可拥有一次完整外框、屋脊/檐口、深青题签和内部纸面，但其内部 Run 行不得再有外卡、阴影或重复屋檐。
4. 四项导航由真实名称、序号和状态承担理解；云水与图标只承担方位和节奏，不能遮挡文字、焦点或操作。
5. 参考图的深青、暖白、矿物金、结构朱和状态朱应按位置使用。页面纸面必须接近暖白宣纸，而非当前偏黄、偏棕的统一底色。
6. 顶栏中的参考性设置/账户图形不能照搬为假按钮。只有已有行为的入口可以是交互控件；其余空间以真实边界文字或留白处理。

## 4. 素材与适配规则

R3 不使用参考截图、带文字图、带水印图或远程素材。需要位图时，只生成本地、无文字、可追溯的材料构件：

| 构件 | 允许职责 | 适配方式 |
| --- | --- | --- |
| 宣纸纹理 tile | 页面及账册纸面材质 | 无接缝低对比平铺，不压状态文字 |
| 深青漆纹 tile | 主殿与 Catalog 题签 | 只使用中心可平铺区域 |
| 云水横幅 | 导航与标题之间的一次过渡 | 保留 alpha，按原比例单次显示 |
| 四枚导航图标 | 公共视图方位识别 | 固定尺寸装饰图，文字名称仍是主信息 |
| 命令门 | 一个真实操作门 | 左端、中段、右端或九宫格构件，不能整图拉伸 |
| Catalog 正殿框 | 整个账册的唯一建筑框架 | 四角、边、顶檐和中心材质分件；边框不覆盖正文 |
| 行级图标 | Run 类型/进入方向的辅助提示 | 小型本地图标；不能替代文字状态或按钮名称 |

生成素材之前必须先建立“构件 proof sheet”，逐件检查透明边缘、色相、可重复中段、无文字和无水印。
只有 proof sheet 通过用户审阅，素材才可进入页面。CSS 只负责尺寸、切片与状态，不伪造绘画细节。

## 5. 严格切片

### R3-A：参考图测量、外部布局校准与构件 proof sheet

- 把参考图拆成主殿、过门、导航、命令门、正殿、账册六个空间区域，记录桌面比例、留白、色相与权重；
- 以 1.1 的三条结论复核六个区域：只有 Catalog 承担连续数据面，只有命令门承担当下真实操作，
  顶栏只承担稳定全局外壳；不得把通用后台侧栏、KPI 卡片或假控制带回构图；
- 生成或整理上节所列的无文字本地构件，制作独立 proof sheet；
- 不接入 Vue 页面，不改 CSS，不产生“看起来差不多”的候选。

退出条件：用户确认构件本身的颜色、纹理、金属感和透明边缘接近目标，没有贴图边缘或现代 UI 图标感。

### R3-B：只重建 Catalog 桌面构图

- 以真实 Catalog 和真实导入操作填充 1440px 结构，不使用假 Run、假设置或截图；
- 为命令门和 Catalog 正殿建立各自唯一的结构容器；Run 行保持连续账册；
- 删除被替换范围内的旧 CSS 所有者，禁止在文件末尾追加“final override”；
- 首轮只做 `1440x960` 与参考图并排审阅，不抢跑移动端和其他视图。

退出条件：用户在真实浏览器中确认首屏的比例、空间层级、色彩和材质已进入正确方向；否则退回 R3-A，
不向 R3-C 叠加新功能或新页面。

### R3-C：内容压力与交互保持

- 用真实长 Run ID、`PASS / FAIL / ABORTED + PENDING`、Catalog error/empty、选择/返回焦点路径压测 R3-B 构图；
- 执行既有前端测试、lint、type-check、生产构建；
- 在真实生产浏览器检查 Console、Network、根溢出、同源资源与无解释 4xx/5xx。

退出条件：参考图的秩序没有因真实数据而崩坏，且现有行为合同未漂移。

### R3-D：单独预注册响应式适配

R3-C 通过且用户确认桌面后，才新建一份移动端合同。它必须重新设计窄屏空间，不能把桌面正殿截图缩小；
不在本合同中预先承诺具体实现。

## 6. 停止条件

出现任一情况立即停止当前切片：

- 试图用截图、带文字图或水印素材掩盖页面结构问题；
- 为还原视觉而引入假设置、假账户、假导出或没有行为的按钮；
- 同一事实获得“外框 + 内框 + 状态框”三层同权重边界；
- 因重建表现而改变 Catalog/API、文件导入、Verdict、URL/history、键盘、焦点、隐私或 `data-testid`；
- 用户认为方向仍然错误。审美否决是退回上一个切片的硬门，不是继续堆 CSS 的理由。
