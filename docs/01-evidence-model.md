# 01. 证据与实验模型

## 1. 设计目标

证据模型必须同时支持：

- 因果可归因的单变量实验；
- 显式声明的组合交互实验；
- 带随机种子的可复现扰动；
- 资源中止、执行错误与业务失败的分离；
- 自动化、浏览器和权威事实的交叉验证；
- 不依赖特定技术栈的适配器扩展。

## 2. 核心实体

### 2.1 Subject

被验收对象的稳定身份，例如一个仓库、构建物、服务集合或网页。核心只记录标识、版本
和来源引用，不解析业务领域。

### 2.2 ExperimentPlan

版本化实验定义，至少包括：

- 目标问题与预期因果；
- 基线引用；
- 一个主要变量，或显式声明的组合变量集合；
- 受控、干扰和未知变量；
- 批次/Profile 覆盖矩阵；
- 数据集与拓扑；
- 负载模型；
- 故障模型；
- 硬性不变量、降级边界和体验目标；
- 资源预算与停止条件；
- 清理、恢复和复现步骤；
- 所需证据层与裁决规则版本。

计划首次运行前生成内容哈希并封存。任何影响变量、断言、停止条件或裁决的修改都会产生新版本；
旧 Run 永远引用原版本。仅修正文案且不改变语义的变更也应留下审计事件。

### 2.3 Baseline

基线不是“上一次随便成功的运行”，而是可寻址、可验证的比较对象：代码/构建版本、配置
摘要、数据指纹、拓扑、环境指纹、负载定义、资源预算和证据清单均应固定。

基线声明容差与失效条件。代码、配置、依赖、数据、拓扑、浏览器或规则越过容差后状态变为
`EXPIRED`；历史报告仍可读取，但不能继续为新 Run 提供有效担保。

### 2.4 Variable

| 类型 | 含义 | 对结论的影响 |
| --- | --- | --- |
| `PRIMARY` | 本次试图证明影响的唯一主要变量 | 单变量实验只能有一个 |
| `COMBINATION` | 明确设计的交互变量集合 | 必须有组合矩阵与对应基线 |
| `CONTROLLED` | 应保持不变的条件 | 漂移可能导致 `INCONCLUSIVE` |
| `NUISANCE` | 无法完全固定但已知的干扰因素 | 必须观测并进入适用边界 |
| `UNKNOWN` | 运行中发现的未计划变化 | 默认使因果结论 `INCONCLUSIVE` |

变量值应使用结构化类型、单位和来源；不要只保存不可比较的自由文本。

### 2.5 BatchProfile

定义一批共同启动或共同观测的能力、拓扑与预算。每个声明 Profile 都必须进入覆盖矩阵；
顺序随机化时记录算法和种子。批次开始前创建清洁快照，结束后记录残留检查。

### 2.6 Run

一次不可变实验尝试，关联计划版本、基线、代码版本、开始/结束时间、执行状态、证据清单、
环境快照、随机种子和最终裁决。复跑创建新 Run，不覆盖旧事实。

Run 可以属于重复组或配对组，并标记 `BASELINE / TREATMENT / RESTORED_BASELINE / NEGATIVE_CONTROL`。
组内顺序、预热策略和重复次数属于计划事实，不能在看到结果后只保留有利运行。

### 2.7 EnvironmentSnapshot

记录可比较而非隐私泄露的环境事实：操作系统/运行时版本、资源容量与余量、进程/端口摘要、
浏览器版本、实例拓扑、时钟、代理是否存在以及适配器版本。路径、账号、令牌与网络标识默认脱敏。

### 2.8 EvidenceArtifact

证据文件记录：类型、来源、采集时间、所属步骤、内容哈希、大小、脱敏状态、解析器版本与
保留策略。原文件与解析后的结构化事实都应可追溯，但不能把敏感内容复制进报告。

### 2.9 Assertion

断言是对事实的确定性判断，至少包含：输入证据、规则版本、严重性、期望、实际、状态和解释。
规则不能只返回布尔值；必须说明为什么以及使用了哪些证据。

### 2.10 Verdict

裁决由规则计算并可重复执行。用户可以补充证据或修正规则，但不能手工把失败覆盖为通过而
不留下审计事件。

### 2.11 ChangeScope

记录本次变更声明的影响层级、所有者、入口、调用者、公共契约、数据流、下游消费者、
失败边界和预期爆炸半径。采集到的 diff 或运行事实若触及更高层级，应产生范围漂移并升级
所需证据；未升级时裁决为 `INCONCLUSIVE`。

### 2.12 MilestoneGate

里程碑记录依赖、进入条件、退出条件和证据状态：

- `PLANNED`：只有问题、范围和验收合同；
- `IMPLEMENTED`：代码事实存在，但不能表示完成；
- `AUTOMATED`：适用自动化证据通过；
- `RUNTIME_VALIDATED`：真实运行、不变量与恢复证据通过；
- `FROZEN`：证据包、版本和基线已冻结，可供下一里程碑引用。

后继里程碑可以处于 `PLANNED`，但只有全部前置节点达到计划要求的 `RUNTIME_VALIDATED`
或 `FROZEN` 后才能进入 `IMPLEMENTED`。任何绕过都必须被拒绝，而不是记一条普通警告。

## 3. 运行状态与裁决分离

### 3.1 ExecutionStatus

- `PLANNED`：尚未开始；
- `RUNNING`：正在执行；
- `COMPLETED`：计划步骤正常结束；
- `ABORTED`：因资源停止线、用户停止或安全保护提前结束；
- `ERROR`：编排器、适配器或基础设施出现非预期错误。

### 3.2 Verdict

- `PASS`：所需证据齐全，变量可归因，全部硬性不变量通过；
- `FAIL`：至少一个硬性不变量被有效证据否定；
- `INCONCLUSIVE`：变量漂移、证据冲突、环境污染或比较基线无效；
- `PENDING`：尚未达到适用证据要求，包括计划未执行或运行被中止后证据不足。

`ABORTED + FAIL` 可以同时存在，例如中止前已经证明不变量失败；`ABORTED + PENDING`
表示资源保护先触发，尚不足以判断业务正确性。两者不能压扁成一个状态字段。

## 4. 负载语义

模型中不得出现没有定义的单一 `concurrency: 1000`。负载至少可表达：

| 字段 | 含义 |
| --- | --- |
| `virtual_users` | 逻辑用户数量 |
| `in_flight_requests` | 同时在途请求上限 |
| `total_requests` | 本轮请求总数 |
| `target_rps` | 目标每秒请求数 |
| `hotspot_contenders` | 同一资源或键的竞争者数量 |
| `connections` | 长连接数量 |
| `message_rate` | 单位时间消息数 |
| `ramp_steps` | 阶梯及每级持续时间 |
| `think_time` | 用户步骤间等待模型 |

每一级负载先执行不变量与资源检查，再进入下一级。数字没有单位、持续时间和业务形态时，
不得生成容量结论。

## 5. 故障模型

通用故障分类至少支持：

1. `UNAVAILABLE`：完全不可用；
2. `SLOW`：延迟、排队或超时；
3. `INTERMITTENT`：间歇性失败；
4. `RESULT_UNKNOWN`：操作可能完成但响应丢失；
5. `RECOVERY_REPLAY`：重启后的重复投递、重放或状态恢复。

适配器可以添加技术细节，但报告应保留通用分类，使不同项目和组件的结果可比较。

## 6. 证据层

### 6.1 CodeFacts

版本、配置、迁移、接口、状态机、所有权和安全边界等静态事实。

### 6.2 AutomatedEvidence

单元、契约、集成、静态检查、覆盖率和自动 E2E。它证明可重复检查，不自动等于真实系统成立。

### 6.3 RuntimeEvidence

真实 HTTP/浏览器、进程与端口、资源曲线、数据库/缓存/消息事实、多实例、故障恢复和最终状态。

计划声明哪些层为必需。缺失必需层只能得到 `PENDING`，不能用另一层替代。

## 7. 不变量与降级

断言严重性分为：

- `HARD`：失败直接导致 `FAIL`；
- `DEGRADATION_BOUNDARY`：允许降级，但必须满足回源、延迟、隔离或恢复边界；
- `OBJECTIVE`：体验或性能目标，失败影响质量评分但不覆盖硬性事实；
- `OBSERVATION`：只记录，不参与裁决。

核心事实与辅助能力由被测项目声明。验迹不内置订单、库存等领域规则，只提供表达、采集和裁决机制。

## 8. 可比较性与污染

Run 与 Baseline 比较前应检查：

- 代码、配置、数据和拓扑是否在允许差异内；
- 时钟、代理、浏览器、运行时和适配器是否发生未声明变化；
- 上一批进程、端口、容器、连接、队列或临时数据是否残留；
- 资源起点是否在预算容差内；
- 随机种子、批次顺序和故障参数是否可复现。
- 计划是否在运行前封存，基线是否仍在有效期内；
- 采集器自身开销是否在容差内，是否需要无采集对照。

无法清理或解释的漂移写入污染清单，并默认产生 `INCONCLUSIVE`。

## 9. 报告最小内容

每份报告必须回答：

- 测了什么，为什么测；
- 与哪个基线比较；
- 唯一主要变量或组合矩阵是什么；
- 负载数字的完整语义是什么；
- 哪些资源停止线生效；
- 哪些证据支持或反驳不变量；
- 是否存在污染、冲突、缺失或人工判断；
- 结论的适用边界与复现方式；
- 证据清单与哈希。
- 变更层级、实际爆炸半径、消费者矩阵和里程碑门禁状态。
