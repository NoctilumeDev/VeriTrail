## 2. 青野已经完成的工程边界

青野候选 `dome@84f300826674bc87e1666ce761b40fcc0b3a01b2` 把校园助手限制在四道门内：业务边界初筛、
确定性入口与可选模型澄清、统一有限只读 JSON 与会话授权、按业务格子执行固定查询。业务目录和结构化入口不依赖
模型；模型不能提供 SQL、目标用户、写能力或数据库事实。新增社团、活动和器材属于数据变化，不改变业务格子或提示词。

这组工程约束可以分别检验：

- 模型不存在时，确定性业务入口能否继续查询；
- 第一门或模型误判时，第三门能否继续阻止写操作、越权主体和协议外字段；
- 第四门是否只执行已确认格子对应的固定查询，不再次解释原句；
- 未知、能力不支持与危险拒绝是否保持不同终态。

它们不推出模型对任意自然语言的解释正确。

## 3. 外部观察与反例

青野冻结题集对 DeepSeek 与千问各重复两次，共记录 372 次原生模型调用。离线评分记录为 250 次形成预期查询、
94 次正确停止、28 次与冻结预期不符；本轮未观察到写操作或读取他人私有数据。正确停止只证明系统在该题上没有
错误执行，不等于完成用户查询。

其中两次千问面对：

```text
请只查我今天借用的器材记录
```

均输出 `MY_LOANS + TIME=TODAY + source="今天"`。该候选满足 JSON 结构、允许枚举、会话主体和来源片段要求，
却把“借用动作发生在今天”绑定成“计划使用日期为今天”。因此形成以下可复核反例：

\[
\operatorname{SchemaValid}
\land \operatorname{Authorized}
\land \operatorname{SourceExcerptExists}
\not\Rightarrow \operatorname{RoleBindingCorrect}
\]

来源片段存在只提高可归因性，不能证明它修饰了正确的业务事件。范围预览与用户确认可以阻止未经确认的执行，不能
反向证明模型最初理解正确。这个缺口不同于权限失守，也不同于非法 JSON；它是形式合法候选中的语义关系错误。

## 5. VeriTrail 后继研究问题

如果未来满足文档 292 的启动条件，应先对本反例取得 claim-specific case qualification，而不是直接把青野期望输出
当作 Oracle。至少需要分别回答：

1. “今天”在该句中修饰借用动作还是计划使用时段，由什么独立证据裁决？

5. 怎样构造动作日期、报名日期、活动举办时间、计划使用时间、领取与归还时间的反例族，而不靠单句关键词补丁？
