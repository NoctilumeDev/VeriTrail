# VeriTrail 0.12.0 Release Notes

VeriTrail 0.12.0 是首个稳定 GitHub Release，也是 M0–M14 收束后的 Core 冻结版本。

它不是“自动把项目判成绿色”的测试按钮，而是一套本地优先、失败保留、确定性裁决的验收证据工作台：
冻结 Plan/Profile，运行受控目标，收集真实浏览器与资源事实，生成不可变 Bundle，再通过明确规则形成
`PASS / FAIL / INCONCLUSIVE / PENDING`。

## 本版包含

- Python Core：seal、evaluate、preflight、bounded run、Catalog、Comparison、Pairing、Batch；
- Windows 受控命令与单/双节点有界目标生命周期；
- Playwright/Chromium 回环浏览器证据；
- 只读 Palace Evidence Workbench；
- 安全整改后的路径、来源、回环、子进程、工件与展示边界；
- wheel、sdist、独立 Workbench ZIP、机器可读验证摘要和 SHA-256 清单。

## 安装

下载 `veritrail-0.12.0-py3-none-any.whl` 后：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install .\veritrail-0.12.0-py3-none-any.whl
```

需要浏览器采集时安装冻结依赖并下载 Chromium：

```powershell
.\.venv\Scripts\python.exe -m pip install "playwright==1.62.0"
.\.venv\Scripts\python.exe -m playwright install chromium
```

需要 Windows 受控命令能力时：

```powershell
.\.venv\Scripts\python.exe -m pip install "pywin32==312"
```

这些可选依赖必须由用户显式安装；VeriTrail 不自动修改全局 Python，也不在缺失时静默降级为不受控
进程实现。

## 最小使用

```powershell
.\.venv\Scripts\veritrail.exe seal `
  --plan .\examples\minimal\plan.json `
  --output .\artifacts\sealed-plan.json

.\.venv\Scripts\veritrail.exe evaluate `
  --plan .\artifacts\sealed-plan.json `
  --evidence .\examples\minimal\evidence-pass.json `
  --run-id first-run `
  --output .\artifacts\first-run
```

每个 Run ID 必须唯一。不要覆盖旧 Run，也不要在看到结果后修改原 Plan 的断言或停止线。

## Workbench

解压 `veritrail-workbench-0.12.0.zip`，然后让固定回环只读 Catalog 服务使用该目录作为
`--web-root`。Workbench 只展示 Bundle、Comparison、Pairing 与 Batch；它不会重算或改写 Verdict。

建议先以仓库示例构建 Catalog，再执行：

```powershell
.\.venv\Scripts\veritrail.exe catalog-serve `
  --catalog .\artifacts\catalog `
  --artifacts .\artifacts\runs `
  --web-root .\veritrail-workbench-0.12.0 `
  --port 18784
```

`--catalog` 使用 `catalog-build --output` 生成的完整目录；服务固定绑定 IPv4 loopback，不能通过参数
扩大到外部接口。

## 双真实目标终验

发布前完成两类独立真实目标：

1. **VeriTrail 自证目标**：常规和优化模式各 13 个预注册出口，覆盖 PASS、FAIL、PENDING、
   INCONCLUSIVE、ABORTED、ERROR、恢复 Comparison、资源停止和清理；
2. **InkNarratives 精确提交**：常规和优化模式均得到
   `PASS / FAIL / PENDING / PASS`，恢复 Comparison `MATCH`、0 differences，损坏副本被 Catalog
   隔离，目标原生 verifier 前后均通过。

完整数据、资源峰值与提交坐标见
[M14 最终验证与发布事实](56-m14-final-validation-and-release-facts.md)。

## 安全结论与边界

最终标准安全扫描覆盖 375 个文件和 12 个攻击面，可报告发现为 0；两轮旧扫描中的 15 项有效问题已
在文档 55 的重新基线流程中关闭。Python、npm、生产构建、wheel/sdist 安装与真实浏览器均已复验。

仍需明确：

- 结构化可信命令不是恶意代码沙箱；
- Windows Job Object 约束自有进程树，不证明宿主机已被隔离；
- 截图像素可能包含业务信息，必须由操作者审查后再共享；
- Subject 自身的文件写入和网络权限仍由宿主权限决定；
- AI 可以帮助解释或起草，不拥有 seal 和 Verdict 权限。

## 失败恢复

- `ABORTED`：资源、用户取消或所有权停止；保存现场后清理，再创建新 Run；
- `PENDING`：证据尚未取得，不等于失败；
- `INCONCLUSIVE`：变量污染、来源漂移或证据冲突；重新封存新计划；
- `FAIL`：适用硬性不变量被证据否定；保留失败 Bundle，不降低断言；
- `ERROR`：采集、staging 或 cleanup 未完成；先处理基础设施与残留，不伪造业务结论。

## 下一步不在本 Release 中

Core 0.12.0 在此冻结。面向初学者的 `VeriTrail Starter` 和可选的
`VeriTrail Authoring Skill` 应作为独立入口层：只能生成 `DRAFT / NOT SEALED`，不能自动封存、
降低断言或决定 Verdict。通用探测、GUI 向导和更多框架预设不会回填到本次冻结结论。
